MÓDULO ALUMNO · MAPA DE CONEXIONES E INTEGRACIONES

Conexiones y Contratos entre Módulos

Especificación técnica detallada de las 4 conexiones estratégicas que debe realizar el Módulo Alumno con los demás componentes del sistema (Autenticación, Administración, Asistencia y Profesor). Define los endpoints consumidos, datos enviados/recibidos, flujo de autenticación JWT y manejo de excepciones.

01

Conexión con Módulo Autenticación

Módulo Autenticación
Módulo Alumno ── POST /auth/login ──► Módulo Auth ── Retorna JWT Token ──► Guardado Contexto

Propósito: Validar credenciales de acceso, obtener el token JWT firmado y extraer la identidad del alumno logueado (alumno_id, legajo, email).

GET /auth/me Headers: { "Authorization": "Bearer eyJhbGciOiJIUzI1Ni..." } Response [200 OK]: { "usuario_id": 45, "alumno_id": 1042, "legajo": "ALU-99420", "nombre": "Estudiante", "rol": "ALUMNO" }
Responsabilidad del Alumno
Almacenar el token en memoria/sessionStorage y adjuntarlo en cada petición subsecuente.
Manejo de Errores (401 / 403)
Si el token expira o la cuenta no tiene el flag ALUMNO, se fuerza la redirección al Login central.
02

Conexión con Módulo Administrador

Módulo Administrador
Módulo Alumno ── GET /alumnos/{id}/comisiones ──► Módulo Admin ── Listado de Cursadas ──► Panel Materias

Propósito: Consultar la lista oficial de comisiones y materias asignadas al estudiante durante el período lectivo vigente.

GET /alumnos/1042/comisiones?periodo=2026-1C Response [200 OK]: [ { "comision_id": 12, "materia": "Programación II", "horario": "Lunes y Miércoles 18:00 - 22:00", "aula": "Aula 204 - Sede Central", "profesores": ["Lic. Martín Gómez", "Ing. Laura Ríos"] } ]
Filtro de Seguridad
El backend valida que {id} coincida con el alumno_id verificado en el token.
Caso Borde (Sin Cursadas)
Si retorna un array vacío `[]`, la UI muestra un estado informativo: "No tenés comisiones inscriptas".
03

Conexión con Módulo Asistencia

Módulo Asistencia (Preceptores)
Módulo Alumno ── GET /alumnos/{id}/asistencias ──► Módulo Asistencia ── Métricas & Clases ──► Vista Presentismo

Propósito: Consumir las marcas de presentismo cargadas por preceptores/docentes y recibir el cálculo automático de asistencias.

GET /alumnos/1042/asistencias?comision_id=12 Response [200 OK]: { "comision_id": 12, "total_clases": 16, "asistencias": 14, "porcentaje": 87.5, "estado_regularidad": "REGULAR", "clases": [ { "fecha": "2026-08-10", "estado": "PRESENTE" }, { "fecha": "2026-08-12", "estado": "AUSENTE" } ] }
Consumo Read-Only
El Alumno no puede modificar ni justificar inasistencias a través de este contrato.
Cálculo de Regularidad
El Módulo Asistencia provee el valor porcentaje precalculado para evitar diferencias en frontend.
04

Conexión con Módulo Profesor

Módulo Profesor
Módulo Alumno ── GET /alumnos/{id}/notas ──► Módulo Profesor ── Calificaciones Cátedra ──► Libreta Digital

Propósito: Consultar las calificaciones de exámenes parciales, trabajos prácticos y la condición final oficializada por el equipo docente.

GET /alumnos/1042/calificaciones?comision_id=12 Response [200 OK]: { "comision_id": 12, "evaluaciones": [ { "instancia": "Primer Parcial", "nota": 8, "fecha": "2026-09-05" }, { "instancia": "Trabajo Práctico 1", "nota": 10, "fecha": "2026-09-15" } ], "condicion_final": "EN_CURSADA" }
Sincronización Docente
Las notas son visibles en el portal del alumno inmediatamente después de que el profesor las guarda/oficializa.
Notas Pendientes
Si una evaluación no ha sido tomada o cargada, se excluye o se retorna nota: null renderizando "Pendiente".
