Sistema de Gestión I26

Guía simple sobre los portales, los datos que comparten y las mejoras incorporadas al ecosistema institucional.

Una sola información institucional

Antes, algunas aplicaciones podían trabajar con datos locales o de ejemplo. La decisión actual es que todos los portales usen una única fuente: la API institucional y su base PostgreSQL en Neon. Así, lo que registra un rol autorizado puede ser consultado por los demás roles cuando corresponde.

Portal→API institucional→Base institucional→Información actualizada

Qué cambia en cada sistema

Alumnos

Consulta de materias, asistencia, notas publicadas, comunicados, perfil, mensajes y participación en actividades. También se preparan QR de asistencia, pedidos de corrección de ficha y justificaciones.

Preceptoría

Padrón institucional, asistencia por comisión, justificaciones, avisos, seguimiento y comunicación con estudiantes. Los datos sensibles se consultan solo con permiso y quedan auditados.

Profesores

Comisiones asignadas, asistencia, observaciones y calificaciones. Se integran Agenda académica, mensajería institucional y resumen de notas al backend común, no a una base separada.

Dirección y administración

Altas académicas, carreras, comisiones, cuentas e inscripciones. Conservan el control de datos sensibles, cuentas y configuraciones institucionales.

Centro de Estudiantes

Eventos, inscripciones, comunicados, foros y reclamos. Se amplían cupos, borradores, moderación y seguimiento de cada reclamo.

Auxiliares

Tareas, sectores, incidencias y mantenimiento. Se incorporan turnos, solicitudes de cambio y ausencias para que el equipo pueda coordinarse dentro del sistema.

Cómo se protege la información

  • La cuenta define qué portal y qué datos puede usar cada persona.
  • Las contraseñas y sesiones se gestionan de forma segura; las pantallas no ven claves ni conexiones de base.
  • Las notas, asistencias y registros históricos no se eliminan de forma informal.
  • Las acciones relevantes quedan registradas para control institucional.

Estado de la integración

En implementación y validación

Las pantallas nuevas y las migraciones necesarias ya están registradas en el repositorio. Antes de publicar una versión nueva se validan las rutas de la API, los permisos de cada rol, las migraciones en una base de prueba y el recorrido real desde cada pantalla. De este modo se evita publicar botones o secciones que todavía no puedan guardar información correctamente.
